# Ground-Up Learning App - read this before anything else

## THE SPEC PACKAGE IS THE BIBLE

`docs/spec/` is a 17-document specification. It is the authority on what this product is,
what it teaches, what it requires, and in what order. **It outranks this file, the handoff,
the code, your memory, and anything a previous session told you.**

### The rule

**Never state anything about scope, curriculum, sequencing, or requirements without opening
the relevant document and reading it first.** Not "I recall", not "as established earlier",
not from the handoff summary. Open the file.

Before any claim about what is or is not in scope, run:

```
grep -rn -i "<topic>" docs/spec/ docs/planning/
```

Answering from memory has repeatedly produced wrong statements in this project - claiming
trigonometry was not in the spec (it is), claiming physics/chemistry/biology were out of
scope (they are Phase 24), renumbering roadmap phases in a published report, and
under-counting the curriculum by three units. Every one of those cost real rework. The cost
of opening the file is a few seconds.

### One distinction that keeps being missed

The science course built so far teaches scientific **method** - reasoning, experiments,
measurement, data. It contains no biology, chemistry or physics subject matter. That
matches the vision's "Initial Subject Scope" exactly; subject matter is Phase 24. Never
describe it as covering "science" without that qualifier.

## Binding constraints

- Curriculum content stays separate from application logic. Content is data under
  `content/mvp/`, validated by JSON Schema at load.
- Grading is deterministic. The AI never writes verified state (DEC-003/005/010).
- The append-only event log is the source of truth; progress is a reproducible projection
  (DEC-006). Never make an event mutable.
- BYOK and sync credentials live in `localStorage` only, never in the event log or an
  export (DEC-015).
- ASCII-only source.
- Do not put the model identifier in any pushed artifact.
- Do not open a PR unless explicitly asked.

## Test gate - a phase is not done until all six are green

```
pnpm validate:content && pnpm test && pnpm typecheck && pnpm lint && pnpm build && pnpm test:e2e
```

## Authoring content

Content is generated by a Python script that computes and asserts **every** answer and
refuses to emit JSON if any check fails. Never hand-type an answer. Verify by the inverse
operation. Add each new unit to `content-answers.test.ts` so every answer is graded through
the real validators. See `docs/HANDOFF.md` section 4 for the full pattern and wiring list.
